# 口罩

您的任務是使用以下兩個原始數據集為藥房平台構建後端服務和數據庫：

## A. 原始數據
### A.1. 藥房數據
鏈接：[data/pharmacies.json](data/pharmacies.json)

該數據集包含藥房列表，其中包括藥房名稱、營業時間、現金餘額和口罩產品。現金餘額表示藥房在此平台上商戶賬戶中持有的金額。

> 處理 `pharmacies.json` 中的 `openingHours` 字段時要小心，因為它包含各種時間格式。

### A.2. 用戶數據
鏈接：[data/users.json](data/users.json)

該數據集包含用戶列表，其中包括用戶名稱、現金餘額和購買歷史記錄。現金餘額表示用戶在此平台上錢包中持有的金額。

這些數據集是原始的，意味著您可以在將數據加載到數據庫之前對其進行處理和轉換。

## B. 任務要求
您的任務是構建一個具有適當文檔的API服務器和關係型數據庫，以允許前端客戶端快速直觀地瀏覽數據。前端團隊將依賴您的文檔來構建客戶端應用程序。

前端團隊要求支持以下操作：

* 列出在特定時間和指定星期幾（如果請求）開放的所有藥房。
* 列出由特定藥房銷售的所有口罩，按口罩名稱或價格排序。
* 列出在特定價格範圍內擁有超過或少於 `x` 個口罩產品的所有藥房。
* 檢索在特定日期範圍內按口罩交易總額排名前 `x` 的用戶。
* 計算特定日期範圍內口罩的總數量和總交易值。
* 按名稱搜索藥房或口罩，並按與搜索詞的相關性對結果進行排名。
* 處理用戶購買口罩的流程，可能來自不同的藥房。

在您的存儲庫中，您**必須**包含：

1. API接口的文檔。
2. 運行ETL（提取、轉換和加載）腳本的命令，該腳本處理原始數據集並將其加載到您的數據庫中。
3. 設置服務器和數據庫的命令。

> 如果您發現需求不夠詳細，請設計您的解決方案使其盡可能實際和實用。

## D. 審核過程
您的項目將由至少一名後端工程師審核。

### D.1. 評估標準
1. **(40%) 對編程語言和框架的熟悉程度：**
    - **代碼質量：**
        - 代碼是否簡單、易於理解、可擴展、可重用且可維護？
        - 代碼是否避免不必要的註釋或冗餘塊？
        - 編碼風格是否與語言指南一致？
        - 是否有明顯的安全漏洞？
    - **邏輯設計：**
        - 數據庫設計是否滿足要求並且易於理解和擴展？
        - 原始數據是否在加載到數據庫之前有效地導入和清理？
        - API邏輯是否滿足要求並反映真實世界場景？
    - **MVC架構（可選）：**
        - 設計模式是否符合框架指南？
        - 如果使用框架，解決方案是否避免重新發明輪子？
2. **(30%) 完成任務要求。**
3. **(20%) API質量：**
    - API是否可以獨立於客戶端應用程序進化並添加功能？隨著API的增長，現有客戶端應用程序是否可以繼續運行而無需修改？
    - 所有功能是否都是可發現的，使客戶端應用程序能夠充分利用它們？
    - 避免調用API時出現任何5xx錯誤。
4. **(10%) 溝通：**
    - API文檔是否清晰易懂，前端工程師易於理解？
